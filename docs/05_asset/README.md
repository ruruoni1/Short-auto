# 05 Asset

니혼줍줍에서 이미지, 영상, 오디오를 안전하게 가져오고 장면과 타임라인에서 재사용하기 위한 공통 계약이다.

## 목표

- 원본 파일은 가져온 뒤 수정하지 않는다.
- 동일한 파일은 한 번만 저장하고 여러 곳에서 참조한다.
- 화면은 파일 경로가 아니라 `assetId`로 에셋을 사용한다.
- 썸네일, 프록시, 파형 등 파생 파일은 원본과 분리한다.
- 사용 중인 에셋은 실수로 삭제할 수 없게 한다.
- 가져오기 실패나 앱 종료가 기존 라이브러리를 손상시키지 않게 한다.

## 기본 흐름

```text
사용자 선택 / 드래그 앤 드롭
  -> 임시 영역에 복사
  -> 형식과 크기 검사
  -> SHA-256 계산 및 중복 확인
  -> 미디어 정보 추출
  -> 원본을 불변 저장소에 확정
  -> 썸네일·프록시·파형 생성
  -> 레코드와 검색 인덱스 공개
  -> Scene/Timeline이 assetId로 참조
```

가져오기는 원본 저장과 레코드 기록이 모두 끝났을 때만 `ready`가 된다. 중간 실패 파일은 라이브러리에 노출하지 않고 임시 영역에서 정리한다.

## 저장 구조

```text
assets/
  originals/sha256/<앞 2자리>/<전체 해시>.<확장자>
  derivatives/<assetId>/
    thumbnail.webp
    proxy.mp4
    waveform.json
  records/<assetId>.json
  staging/
  trash/
```

- `originals`: 콘텐츠 해시 기준의 불변 원본
- `derivatives`: 언제든 다시 만들 수 있는 파생 파일
- `records`: `asset-record.schema.json`을 따르는 메타데이터
- `staging`: 가져오기 처리 중인 파일. 사용자 기능에서 직접 조회하지 않는다.
- `trash`: 즉시 영구 삭제하지 않는 복구 대기 영역

프로젝트를 외부로 내보낼 때는 실제 사용 중인 `assetId`만 수집한다. 운영체제의 절대 경로는 프로젝트 문서에 저장하지 않는다.

## 에셋 상태

| 상태 | 의미 | 사용 가능 여부 |
| --- | --- | --- |
| `importing` | 검사 또는 복사 중 | 아니요 |
| `processing` | 원본 확정 후 파생 파일 생성 중 | 원본 사용만 가능 |
| `ready` | 정상 사용 가능 | 예 |
| `failed` | 가져오기 또는 처리 실패 | 아니요 |
| `missing` | 레코드는 있으나 원본을 찾을 수 없음 | 아니요, 다시 연결 가능 |
| `trashed` | 휴지통으로 이동됨 | 기존 참조만 경고 표시 |

## 분류

기계 분류와 사용자 분류를 분리한다.

- 고정 분류: `image`, `video`, `audio`
- 자동 메타데이터: MIME, 크기, 재생 길이, 해상도, 프레임률, 오디오 채널, 코덱
- 사용자 분류: 표시 이름, 폴더, 태그, 즐겨찾기
- 출처 정보: `local`, `generated`, `recorded`, `downloaded`

자동 추정값이 사용자 태그를 덮어쓰면 안 된다. 생성형 에셋은 생성 도구와 프롬프트 등 재현에 필요한 정보를 스키마의 `source.generator`에 보관할 수 있다.

## 조회 계약

최소 조회 기능은 다음과 같다.

- `get(assetId)`: 단일 레코드 조회
- `list(filter, sort, cursor)`: 종류, 상태, 폴더, 태그, 생성 시각 필터
- `search(query, filter, cursor)`: 이름과 태그 검색
- `resolve(assetId, variant)`: 원본 또는 파생 파일의 앱 내부 사용 위치 반환
- `usage(assetId)`: Scene/Timeline 등 현재 참조 목록 반환

목록 조회는 대량 라이브러리를 고려해 커서 기반 페이지 이동을 사용한다. UI에 저장소 내부 경로나 콘텐츠 해시를 노출하지 않는다.

## 사용 계약

Scene과 Timeline은 에셋 레코드를 복제하지 않고 공통 `sourceRef`로 참조한다. 타임라인의 시간 단위는 `docs/timeline-contract.md`에 맞춰 마이크로초 정수를 사용한다.

```json
{
  "sourceRef": {
    "kind": "asset",
    "id": "ast_01J..."
  },
  "sourceInUs": 0,
  "sourceOutUs": 4200000
}
```

- 실제 클립 구조와 화면상 재생 범위는 Timeline 계약이 소유한다.
- 영상·오디오의 구간 값은 원본을 자르지 않는 비파괴 편집 정보다.
- 렌더러는 `resolve`를 통해 실제 파일을 얻는다.
- 오프라인 또는 누락 상태에서는 참조를 유지하고 대체 UI를 표시한다.

## 중복과 교체

- SHA-256이 같으면 기존 원본을 재사용하고 새 레코드를 중복 생성하지 않는다.
- 파일명이 같아도 해시가 다르면 별도 에셋이다.
- 에셋 교체는 기존 `assetId`의 원본을 바꾸지 않는다. 새 에셋을 가져온 뒤 참조를 명시적으로 이전한다.
- 참조 이전은 한 번에 되돌릴 수 있는 편집 명령으로 기록한다.

## 삭제 안전성

1. `usage(assetId)`로 참조를 확인한다.
2. 사용 중이면 삭제를 막고 사용 위치를 보여준다.
3. 미사용 에셋은 `trashed`로 전환하고 휴지통으로 이동한다.
4. 영구 삭제는 별도 명령이며 원본과 파생 파일을 함께 제거한다.
5. 동일 원본을 다른 레코드가 참조하면 원본 blob은 유지한다.

## 다른 영역과의 경계

- `01_Core`: ID, 저장소, 이벤트 버스, 오류 형식
- `03_Timeline`: 에셋 구간과 사용 참조의 소유자
- `04_Scene`: 장면 내 배치, 크기, 자르기, 불투명도 등 표현 속성의 소유자
- `06_Theme_Motion`: 에셋에 적용하는 스타일과 모션의 소유자
- `08_ReviewEditor`: 누락·저해상도·무음 등 품질 경고의 소비자
- `12_Integration`: 가져오기, 저장, 패키징, 렌더 연결의 통합 검증

Asset 영역은 원본과 파생 파일의 생명주기까지만 책임진다. 장면 레이아웃이나 타임라인 편집 상태를 에셋 레코드에 넣지 않는다.

## 도메인 이벤트

다른 영역은 내부 파일을 감시하지 않고 다음 이벤트를 구독한다.

- `asset.import.started`
- `asset.import.progress`
- `asset.ready`
- `asset.processing.failed`
- `asset.metadata.updated`
- `asset.trashed`
- `asset.restored`
- `asset.missing`
- `asset.relinked`

각 이벤트에는 최소한 `eventId`, `assetId`, `occurredAt`, `projectId`를 포함한다. 진행률 이벤트를 제외한 이벤트는 중복 수신되어도 같은 결과가 나와야 한다.

## 완료 기준

- 이미지·영상·오디오 각 1개를 가져와 `ready` 상태로 조회할 수 있다.
- 같은 파일을 두 번 가져와도 원본은 하나만 저장된다.
- 앱을 가져오기 도중 종료해도 기존 레코드가 손상되지 않는다.
- Scene/Timeline 문서에 절대 파일 경로가 남지 않는다.
- 사용 중인 에셋 삭제가 차단되고 사용 위치가 표시된다.
- 삭제한 미사용 에셋을 휴지통에서 복구할 수 있다.
- 원본 누락 후 다시 연결해 기존 참조가 복구된다.
- 파생 파일 삭제 후 자동 재생성할 수 있다.

## 다음 구현 순서

1. Core가 정한 언어와 저장소에 맞춰 `AssetRepository` 인터페이스를 확정한다.
2. 원자적 가져오기와 SHA-256 중복 제거를 구현한다.
3. 미디어 메타데이터 추출과 파생 파일 작업 큐를 연결한다.
4. 목록·검색·태그·폴더를 구현한다.
5. Scene/Timeline 참조와 삭제 보호를 통합한다.
6. 누락 파일 다시 연결과 프로젝트 패키징을 검증한다.
