# 니혼줍줍 데스크톱 출시 기준

> 기준일: 2026-09-04 (Asia/Seoul)  
> 담당: `11_Desktop_Release`  
> 상태: Electron·Windows 11·GitHub Releases 기준 확정 / 패키징 구현 대기

## 현재 판단

- 현재 저장소에는 데스크톱 앱 소스와 패키지 설정이 없다.
- 데스크톱 Shell은 Electron, 1차 지원 환경은 Windows 11 x64, 정식 배포 위치는 GitHub Releases로 확정한다.
- Electron용 세부 패키징·자동 업데이트 라이브러리는 앱 골격과 보안 요구사항을 확인한 뒤 선택한다.
- 첫 앱 골격이 들어오면 이 문서의 공통 출시 기준을 실제 명령과 자동 검증으로 연결한다.
- 미서명 개발 빌드와 사용자에게 배포하는 정식 빌드를 명확히 구분한다.

## 출시 목표

니혼줍줍의 정식 버전은 사용자가 Windows에서 안전하게 설치하고, 기존 작업을 잃지 않은 채 업데이트하거나 이전 버전으로 복구할 수 있어야 한다. "빌드 성공"만으로 출시 완료로 판단하지 않으며, 실제 설치·실행·업데이트·제거까지 확인한다.

## 버전 관리 원칙

- 버전 형식은 `MAJOR.MINOR.PATCH`를 사용한다.
- `MAJOR`: 프로젝트 파일 또는 사용자 데이터와 호환되지 않는 변경
- `MINOR`: 하위 호환되는 기능 추가
- `PATCH`: 하위 호환되는 오류 수정과 내부 개선
- 시험 배포는 `X.Y.Z-beta.N` 형식을 사용한다.
- 앱 안의 표시 버전, 패키지 메타데이터, 설치 파일 이름, 업데이트 정보의 버전은 반드시 일치해야 한다.
- 기술 스택 확정 후 하나의 파일을 버전의 단일 원천으로 지정하고 나머지는 빌드 과정에서 생성한다.
- Git 태그는 정식 버전 `vX.Y.Z`, 시험 버전 `vX.Y.Z-beta.N` 형식을 사용한다.
- 이미 배포한 같은 버전의 설치 파일을 다른 내용으로 교체하지 않는다. 수정이 필요하면 새 버전을 발행한다.

## 배포 채널

| 채널 | 대상 | 목적 | 업데이트 규칙 |
|---|---|---|---|
| 개발 | 내부 개발자 | 빠른 기능 확인 | 자동 업데이트 없음 |
| 베타 | 제한된 시험 사용자 | 설치·업데이트·회귀 확인 | 베타 버전만 수신 |
| 정식 | 일반 사용자 | 안정 버전 제공 | 베타 버전을 수신하지 않음 |

베타와 정식 업데이트 정보 및 저장 위치는 분리한다. 정식 사용자가 시험 버전을 받는 경로는 허용하지 않는다.

## Windows 패키지 요구사항

- 64비트 Windows용 설치 파일을 기본 산출물로 제공한다.
- v1의 1차 지원 범위는 Windows 11 x64다. 추가 Windows 버전과 CPU 아키텍처는 환경 조사 후 확장 여부를 결정한다.
- 설치 범위(현재 사용자 또는 모든 사용자), 기본 설치 경로, 바로가기 생성 여부를 문서화한다.
- 앱 이름, 게시자, 아이콘, 실행 파일 이름, 설치 프로그램의 표시 이름을 일관되게 유지한다.
- 정식 설치 파일과 실행 파일은 신뢰 가능한 코드 서명을 적용한다.
- 인증서와 서명 비밀번호는 저장소나 빌드 로그에 남기지 않는다.
- 사용자 프로젝트와 설정은 앱 설치 폴더 밖에 저장해 업데이트·제거 과정에서 우발적으로 삭제되지 않게 한다.
- 자동 업데이트는 내려받기 실패, 서명 불일치, 디스크 부족, 앱 재시작 거부 상황을 안전하게 처리해야 한다.

## 필수 출시 산출물

정식 버전마다 아래 항목을 함께 보관한다.

1. 버전이 포함된 Windows 설치 파일
2. 자동 업데이트용 메타데이터와 차등 파일(사용하는 도구가 생성하는 경우)
3. SHA-256 체크섬 목록
4. 사용자 대상 변경 내역
5. 내부 출시 검증 기록
6. 대응되는 Git 커밋과 태그

설치 파일 권장 이름은 `NihonZupZup-Setup-X.Y.Z-x64.exe`이다. 최종 제품 표기가 확정되면 한 번만 변경하고 이후 버전에서 유지한다.

## 출시 관문

### 1. 버전·소스 일치

- 작업 폴더에 의도하지 않은 변경이 없다.
- 버전 단일 원천, 앱 표시 버전, 설치 파일, 업데이트 정보가 일치한다.
- 변경 내역에는 사용자에게 보이는 변경과 알려진 제한이 기록되어 있다.
- 프로젝트 파일 형식 변경이 있으면 마이그레이션과 하위 호환 여부가 명시되어 있다.

### 2. 자동 검사

- 의존성 설치가 잠금 파일 기준으로 재현된다.
- 정적 검사, 단위 테스트, 통합 테스트가 모두 통과한다.
- 배포 모드 빌드가 깨끗한 환경에서 성공한다.
- 설치 파일과 업데이트 파일의 체크섬을 생성하고 다시 검증한다.
- 정식 파일의 디지털 서명과 타임스탬프가 유효하다.
- 비밀값, 개발용 주소, 로컬 절대 경로, 디버그 설정이 산출물에 포함되지 않는다.

### 3. 실제 Windows 검증

- 신규 설치 후 앱이 정상 실행된다.
- 경로에 한글과 공백이 있어도 프로젝트 생성·저장·재열기가 된다.
- 일반 사용자 권한에서 핵심 기능이 동작한다.
- 큰 미디어 파일과 누락된 미디어를 열 때 앱이 손상 없이 안내한다.
- 앱 종료 후 다시 실행해 최근 작업과 설정이 유지된다.
- 이전 정식 버전에서 새 버전으로 업데이트해 사용자 프로젝트와 설정이 유지된다.
- 업데이트 중 네트워크를 끊어도 기존 버전을 다시 실행할 수 있다.
- 제거 후 사용자 프로젝트가 남고, 앱 전용 임시 파일 처리 방식이 예상과 일치한다.
- 설치 파일, 설치된 앱, 앱 정보 화면의 버전이 모두 같다.

### 4. 출시 승인

- 중대 또는 높음 등급의 미해결 결함이 없다.
- 설치·업데이트·롤백 검증 근거가 기록되어 있다.
- 배포 위치의 파일을 직접 내려받아 체크섬과 서명을 재확인했다.
- 정식 채널에서 해당 버전이 실제로 노출되는지 확인했다.
- 문제가 발생했을 때 되돌릴 이전 정식 버전과 절차가 준비되어 있다.

## 업데이트 안전 규칙

- 앱 시작 직후 사용자 작업을 막는 강제 업데이트를 기본값으로 사용하지 않는다.
- 자동 저장 또는 내보내기 중에는 업데이트 설치를 시작하지 않는다.
- 업데이트 전 현재 작업 저장 여부를 확인하고 사용자가 재시작 시점을 선택할 수 있게 한다.
- 다운로드한 업데이트는 서명 또는 공급망 무결성 검증을 통과한 뒤에만 실행한다.
- 프로젝트 파일을 마이그레이션하기 전 복구 가능한 사본을 만든다.
- 새 버전에서 프로젝트를 저장하면 구버전에서 열 수 없는 경우, 저장 전에 분명하게 알린다.
- 업데이트 실패 시 설치가 반쯤 적용된 상태로 남지 않도록 원자적 교체 또는 검증된 설치 프로그램 복구 기능을 사용한다.

## 롤백 기준

다음 중 하나가 확인되면 새 배포를 중단하고 이전 정식 버전을 다시 기본 버전으로 제공한다.

- 앱 실행 또는 설치 실패가 반복됨
- 사용자 프로젝트·미디어·설정 손상 가능성
- 내보내기 결과의 중대한 오류
- 업데이트 루프 또는 복구 불가능한 업데이트 실패
- 서명·업데이트 정보·배포 파일 불일치
- 보안상 중대한 취약점 또는 비밀값 노출

롤백은 설치 파일만 되돌리는 것으로 끝내지 않는다. 업데이트 정보, 다운로드 페이지, 변경 내역을 함께 되돌리고 영향받은 데이터 형식의 복구 가능성을 확인한다.

## Electron 앱 골격 확정 직후 할 일

1. Electron 패키징 도구와 GitHub Releases 자동 업데이트 제공 방식을 결정한다.
2. 버전 단일 원천과 앱 내부 버전 표시 위치를 연결한다.
3. 개발·베타·정식 빌드 설정을 분리한다.
4. 반복 가능한 패키징 및 체크섬 생성 명령을 추가한다.
5. 서명 없는 내부 빌드와 서명된 정식 빌드의 자동 검증을 분리한다.
6. 깨끗한 Windows 환경에서 설치·업데이트 검증 절차를 자동화한다.
7. 실제 배포 저장소와 권한, 보존 기간, 롤백 담당자를 기록한다.

## 완료 정의

이 영역의 첫 출시 준비는 다음 조건을 모두 만족할 때 완료다.

- 실제 앱 소스에 패키징 설정이 존재한다.
- 한 명령 또는 자동 작업으로 재현 가능한 설치 파일이 생성된다.
- 버전과 산출물 일치 검사가 자동화되어 있다.
- 신규 설치, 이전 버전 업데이트, 실패 복구, 제거 검증이 통과한다.
- 배포된 파일의 체크섬과 서명이 확인된다.
- 출시 및 롤백 절차가 실제 배포 위치 기준으로 갱신되어 있다.
