# 니혼줍줍 통합 기준선

> 기준일: 2026-09-04 (Asia/Seoul)  
> 담당: `12_Integration`  
> 상태: 계약 기준선 검증 완료 / 실행 가능한 앱 대기

## 현재 결론

현재 프로젝트에는 실행 가능한 애플리케이션 코드가 없다. 따라서 기능 회귀나 설치 회귀를 통과했다고 선언할 수 없다. 지금 검증 가능한 범위는 모듈 계약, 문서 참조, JSON 스키마, 디자인 토큰, 출시 관문의 일관성이다.

`scripts/verify-integration.ps1`은 이 기준선을 자동 확인한다. 앱 골격이 추가되면 같은 스크립트를 단위 테스트, 통합 테스트, 빌드, 설치 스모크 테스트의 단일 진입점으로 확장한다.

## 통합 소유권

| 데이터·동작 | 단일 소유 모듈 | 다른 모듈의 사용 방식 |
| --- | --- | --- |
| 프로젝트 ID·저장·이벤트·공통 오류 | Core | 공개 계약을 통해 사용 |
| 시간 배치·트랙·클립·재생 범위 | Timeline | 직접 수정하지 않고 명령/API 사용 |
| 자막 문구·번역·스타일 | Caption | Timeline은 `sourceRef`만 보관 |
| 장면 내용·전환·레이아웃 | Scene | Timeline은 `sourceRef`와 시간만 보관 |
| 원본 미디어·파생 파일·메타데이터 | Asset | `assetId`로 참조하고 `resolve`로 위치 조회 |
| 시각 토큰·모션 프리셋 | Theme/Motion | 도메인 데이터에 CSS 값을 복제하지 않음 |
| 검토 의견·승인 스냅샷·품질 결과 | ReviewEditor | 대상 버전과 규칙 버전을 명시 |
| 내부 콘텐츠 상태·검색 메타데이터 | Content Manager | YouTube 원격 상태와 분리 |
| 업로드·게시·원격 동기화 | YouTube | 승인된 내부 버전을 입력으로 사용 |
| 패키징·업데이트·서명·배포 | Desktop Release | 통합 관문 통과 후에만 배포 |

## 공통 계약 결정

- 시간은 `0` 이상의 안전한 정수 마이크로초이며 범위는 `[startUs, endUs)`다.
- 모듈 간 미디어 연결은 절대 경로가 아니라 `{ kind: "asset", id: assetId }` 형태의 `sourceRef`를 사용한다.
- 에셋 생성 정보는 `source.generator`에 저장한다.
- 저장 가능한 문서는 `schemaVersion`을 가지며 변경 가능한 집합은 `revision`으로 동시성을 검사한다.
- 승인 버전은 읽기 전용 스냅샷이며 승인 후 변경은 새 초안과 검토 회차를 만든다.
- 품질 검사 결과의 `검사 불가`는 통과가 아니며 차단 항목 실패 시 승인·게시·배포를 중단한다.
- Content Manager의 `contentStatus`, 제작 파일의 `productionStatus`, YouTube 원격 게시 상태는 서로 다른 필드와 이력으로 관리한다.
- 사용자 프로젝트와 설정은 설치 폴더 밖에 저장하고 업데이트·제거 중 보존한다.

## 전체 사용자 흐름

```text
프로젝트 생성
  -> 에셋 가져오기·검증·불변 저장
  -> 자동 기획 또는 수동 장면 구성
  -> 장면·자막을 타임라인에 sourceRef로 배치
  -> 미리보기·편집·Undo/Redo·자동 저장
  -> 품질 검사와 검토 요청
  -> 필수 의견 해결 및 승인 스냅샷 고정
  -> 렌더·출력 검증
  -> YouTube 업로드·메타데이터·게시 상태 재조회
  -> 설치/업데이트 가능한 데스크톱 릴리스 검증
```

외부 부작용이 있는 YouTube 게시와 정식 배포는 재시도 가능한 내부 처리와 분리하고, 실행 전 대상 버전·채널·공개 상태를 확인한다.

## 회귀 테스트 매트릭스

| 관문 | 최소 회귀 시나리오 | 현재 상태 |
| --- | --- | --- |
| 계약 | JSON 파싱, 필수 문서, `sourceRef`, 시간 단위, 용어 일치 | 자동 검사 통과 필요 |
| Asset ↔ Timeline | 가져온 파일 배치, 중복 원본 재사용, 누락·재연결, 사용 중 삭제 차단 | 코드 대기 |
| Scene/Caption ↔ Timeline | 반열림 경계, 분할·자르기, 링크 이동, 자막 싱크, Undo/Redo 왕복 | 코드 대기 |
| Planner ↔ Editor | 생성 계획 수정, 부분 재생성, 사용자 변경 보존 | 계약·코드 대기 |
| Review ↔ Output | 필수 의견/실패 검사 승인 차단, 승인 버전 고정, 변경 후 재검토 | 코드 대기 |
| Content ↔ YouTube | 내부/원격 상태 분리, 멱등 재시도, 업로드 후 API 재조회 | 계약·코드 대기 |
| 저장·복구 | 자동 저장 중 종료, 마이그레이션, 미디어 누락, 한글·공백 경로 | Core 코드 대기 |
| Desktop Release | 신규 설치, 이전 버전 업데이트, 중단 복구, 제거 | 패키징 대기 |
| 공급망 | 버전 일치, SHA-256 재검증, 코드 서명·타임스탬프 | 정식 빌드 대기 |
| 접근성·모션 | 키보드 흐름, 상태의 비색상 표현, reduced-motion | UI 대기 |

## 출시 차단 조건

다음 중 하나라도 해당하면 최종 연결 완료 또는 출시 완료로 표시하지 않는다.

- 제품 목표·대상 사용자·첫 결과물이 확정되지 않음
- 필수 모듈 계약 또는 마이그레이션 정책이 없음
- 중대/높음 결함, 미해결 필수 의견, 차단 품질 검사 실패가 남음
- `검사 불가` 결과를 통과로 취급함
- 승인한 버전과 렌더·업로드·배포 대상 버전이 다름
- 저장 문서에 로컬 절대 경로나 비밀값이 포함됨
- 설치·업데이트·중단 복구·제거 중 사용자 프로젝트가 손상됨
- 설치 파일, 앱 표시, 업데이트 정보의 버전·체크섬·서명이 일치하지 않음

## 자동 검사 실행

```powershell
pwsh -File .\scripts\verify-integration.ps1
```

검사는 읽기 전용이며 성공 시 검사 항목과 `PASS`를 출력한다. 실패 시 해당 계약을 수정한 뒤 다시 실행한다.

## 앱 골격 추가 후 연결 순서

1. Core가 기술 스택, 프로젝트 파일, ID, 공통 오류와 이벤트 형식을 확정한다.
2. 각 모듈의 계약을 실제 타입 또는 JSON Schema로 옮긴다.
3. 단위 테스트를 모듈별 명령에 연결하고 통합 스크립트가 모두 호출하게 한다.
4. `Asset -> Scene/Caption -> Timeline -> Review -> Output`의 로컬 E2E 고정 샘플을 만든다.
5. YouTube는 가짜 서버/테스트 계정 경로와 실제 게시 전 검증 경로를 분리한다.
6. Desktop Release의 깨끗한 Windows 설치·업데이트·복구 검증을 마지막 관문으로 연결한다.
