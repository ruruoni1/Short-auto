# 애니메이션 품질 점검

이 문서는 검토·승인 화면과 타임라인 편집 화면의 모션을 실제 구현에서 판정하기 위한 기준이다.

## 합격 기준

### 반응성

- 버튼 press 피드백은 입력 후 다음 프레임에 보인다.
- hover/focus 전환은 160ms, 선택·패널 전환은 240ms를 기본값으로 사용한다.
- 클립 드래그, 핸들 리사이즈, playhead scrub에는 transition이 없다.
- 포인터와 조작 대상 사이에 눈에 띄는 지연이나 탄성 효과가 없다.

### 연속성

- 패널을 열 때 기존 콘텐츠가 갑자기 재배치되지 않는다.
- 모달과 패널의 진입 방향은 실제 화면 배치와 일치한다.
- 버전 전환 후 스크롤·선택 위치를 유지할 수 있으면 유지한다.
- 재생 중 playhead는 애니메이션 추정값이 아니라 실제 재생 시간에서 그린다.

### 절제

- 한 화면의 주목을 끄는 큰 모션은 한 번에 하나뿐이다.
- hover에서 카드 또는 버튼은 최대 2px만 상승한다.
- 승인·저장 성공에 confetti, bounce, 반복 pulse를 사용하지 않는다.
- skeleton의 shimmer는 한 화면에서 넓은 면적을 차지하지 않으며 reduced-motion에서는 멈춘다.

### 접근성

- `prefers-reduced-motion: reduce`에서 콘텐츠가 숨은 상태로 남지 않는다.
- reduced-motion에서도 상태 전환은 텍스트, 아이콘, 색상으로 확인 가능하다.
- 키보드 focus 상태는 hover와 같은 정보와 명확한 3px ring을 제공한다.
- 자동 재생되는 장식 모션은 정지할 수 있거나 5초 이내에 끝난다.

### 성능

- 스크롤 및 패널 전환은 transform/opacity 중심으로 구현한다.
- 대형 blur, filter, box-shadow를 프레임마다 바꾸지 않는다.
- 드래그 중 layout 측정은 프레임당 최대 한 번으로 묶는다.
- 개발자 도구 4배 CPU slowdown에서 긴 작업 기준으로 프레임 드롭을 육안 점검한다.

## 화면별 테스트

### 검토 패널

1. 의견 패널을 열고 닫아 본다.
2. 진입 240ms, 종료 160ms이며 닫을 때 본문이 먼저 튀지 않는지 확인한다.
3. 필수 수정 필터를 바꿀 때 목록 높이 변화가 과도하게 흔들리지 않는지 확인한다.
4. 승인 차단 상태가 색상 없이도 이해되는지 확인한다.

### 버전 비교

1. 두 버전을 전환해 추가·삭제 표시가 즉시 갱신되는지 확인한다.
2. 변경 강조가 반복 점멸하지 않는지 확인한다.
3. 긴 문서에서도 전환 중 스크롤이 강제로 맨 위로 이동하지 않는지 확인한다.

### 타임라인

1. clip 이동, trim, split 후 undo/redo를 반복한다.
2. 조작 중 transition이 개입하지 않는지 확인한다.
3. snap 발생 시 선 또는 짧은 색상 변화로만 피드백하는지 확인한다.
4. 29.97fps에서 playhead와 프레임 경계가 흔들리거나 한 프레임 밀리지 않는지 확인한다.
5. 재생 종료 지점에서 playhead가 overshoot하지 않는지 확인한다.

## 구현 완료 증거

- 기본 모션과 reduced-motion 각각의 화면 녹화
- 4배 CPU slowdown 성능 기록 또는 프로파일 캡처
- 키보드 전용 조작 녹화 또는 체크 결과
- 주요 상호작용의 실제 측정 시간
- 발견된 예외와 의도적으로 허용한 차이
